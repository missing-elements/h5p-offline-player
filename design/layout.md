# Layout

A pnpm workspace of eleven parts: nine packages and two apps, the demo and the skills' test project.
Eight of the packages are published to npm; the ninth, the VS Code extension, is a `.vsix`. Paths
elsewhere in this file are relative to the part they belong to — `src/…` and `scripts/…` mean the
player's unless a section says otherwise.

```

  src/
    h5p-offline-player.ts   the <h5p-player> custom element — the only public entry point
    plan.ts                 `./plan` -> dist/h5p-plan.js: the player's library rules (`planPack`, `ownLibraries`,

      stream-utils.ts       sliceStream, the stream opened only when read, and the native inflate: the server,
                            the Jobs worker and the warm all take them from here, since 2026-10-15
    sw/

      mount.ts              mountH5P(self)     -> dist/h5p-sw-mount.js; the virtual file server
      package-reader.ts     zip index + per-entry serving strategy
      pack-plan.ts          which parts of the pack a package needs, and which of its own folders they
                            replace (`planPack`): pure, unit-tested in tests/unit/pack-plan.test.ts
      library-load.ts       what a frame loads, its libraries' scripts and styles in order (`LibraryLoad`),
                            which the `boot` route answers: h5p-standalone's walk and sort, ported (#37)

                            frame-boot.js with `<script nonce src>`, the script itself is the runtime package's
      watermark-wait.ts     the stall-bounded wait for an entry's bytes, and what counts as progress
      routes.ts             URL shape of the virtual routes

      jobs-worker.ts        downloads, extractions and warming; the only long-running code, and it carries no zip.js
      job-queue.ts          the order extractions run in: one at a time, demand first, promotion on a repeat

  tests/fixtures/src/       the source of the generated .h5p archives

  public/                   generated, not in git: the runtime's dist/ as frame-assets/, and the test fixtures
  page/                     page.css and mark.svg, copied to dist/ by build-workers (#170): the page around the
```

`vercel.json` and `api/` stay at the repository root, which is the Vercel project's root: moving
them into `apps/demo/` would need the project's Root Directory changed in the dashboard as well.

**The demo compiles the element from the player's source.** The pages import
`@missing-elements/h5p-offline-player` through `demo/element.js`, and `apps/demo/vite.config.ts`
aliases that name to `packages/player/src/h5p-offline-player.ts`, with the player's plugins
supplying the Jobs worker and the dev Service Worker. So dev needs no player build and edits
show up at once — and the demo does *not* exercise the published `dist/` the way a consuming app
does, which is how a user's build rather than ours found the missing assets and licence notices
of 0.1.5. Pointing the demo at `dist/` is a separate decision, since it changes the deployed
layout. Two things follow from the source path: in dev the Service Worker's scope is
`/@fs/…/packages/player/src/h5p/`, because Vite serves files outside the app's root under
`/@fs/`; and the demo's dev server serves the player's `public/` as its own, which is where the
element looks for `/frame-assets/` in dev.
